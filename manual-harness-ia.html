1O que é isso

Duas coisas diferentes, que convivem: o harness (o que você ensina para o Copilot) e o harness-metricas (a camada que mede o resultado disso).

Harness

São os arquivos de customização do Copilot no VS Code: instructions, prompts, agents, skills e hooks. É o que faz o agente conhecer o padrão do time, seguir o fluxo SDD e respeitar as travas.

harness-metricas

Um coletor que observa as sessões que você escolher e um comando que gera um painel HTML com tempo, guard-rails, tokens, custo e qualidade — para apresentar a resultado, não a achismo.

Três regras que evitam 90% dos problemas

  • Nada é medido sem você pedir. O coletor só grava a sessão depois que você escreve #medir num prompt. Sem isso, nem o SessionStart entra.
  • Nada de conteúdo vai para disco. Nem prompt, nem código, nem texto de comando. Só metadado (ver a seção de privacidade).
  • Nada é commitado nos repos de produto. Os arquivos em .github/ ficam locais e entram no .git\info\exclude.

As três regras de precedência que mordem

  • Hook de workspace ganha do hook de usuário para o mesmo evento. Se o repo já tem .github/hooks/*.json, instale o coletor também nele.
  • Agent de usuário mascara o do repositório quando têm o mesmo nome — e você fica com uma versão velha sem perceber.
  • Skill carrega por descrição. A description do SKILL.md fica sempre no índice e custa token em toda requisição; o corpo só carrega quando o pedido casa.
Política do banco

Não commite nada dentro de .github/ nos repositórios de produto. Deixe os arquivos locais e registre no .git\info\exclude. Para skills, .agents/skills/ é a alternativa quando a restrição é só sobre .github/.

# marcar os artefatos locais como não versionados (PowerShell, dentro da pasta do repo)
Add-Content .git\info\exclude ".github/"
Add-Content .git\info\exclude ".agents/"

3Instalar o pacote na sua máquina

Node 18+ e nada mais: sem npm install, sem extensão, sem admin. Se algum comando falhar, o doutor (passo 6) diz exatamente o porquê.

Descompacte e coloque a pasta no lugar

O zip traz uma pasta harness-metricas dentro. É essa pasta que vai para C:\Users\i459249\.copilot\harness-metricas — cuidado com a pasta dentro de pasta que o Windows cria ao extrair.

# confira que o arquivo principal está no lugar certo:
dir "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs"

# se não achar, procure onde ele foi parar (PowerShell):
Get-ChildItem -Path $env:USERPROFILE -Filter hm.mjs -Recurse -ErrorAction SilentlyContinue | Select-Object -First 5 FullName
Se o caminho for outro

Use o caminho que a busca imprimiu em todos os comandos abaixo (trocando a parte C:\Users\i459249\.copilot\harness-metricas), ou mova a pasta para o caminho acima. No cmd, a mesma busca é dir /s /b %USERPROFILE%\hm.mjs.

Confira o Node

node -v

Precisa ser v18 ou maior. Se aparecer "não é reconhecido", o Node não está no PATH deste terminal.

Teste o comando

A CLI é sempre invocada pelo caminho completo do arquivo. Essa forma funciona igual no PowerShell, no cmd e no Git Bash, e de qualquer pasta corrente — é a forma usada no manual inteiro:

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" ajuda

Se imprimir harness-metricas v… e a lista de comandos, está instalado. Daqui em diante, onde o manual mostrar node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" …, é literalmente isso que você digita.

Não crie atalho com %HM%

Variável no formato "%HM%" só existe no cmd. O terminal integrado do VS Code no Windows é PowerShell, e lá "%HM%" ajuda falha com Token 'ajuda' inesperado — o PowerShell trata a linha inteira como texto. Se quiser mesmo um atalho, veja a caixa no fim desta seção; se não quiser pensar nisso, use o caminho completo acima e ignore o resto.

Instale os hooks

Só num repositório (recomendado quando você quer medir um projeto específico):

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" instalar --workspace "C:\Users\<voce>\Documents\Projetos\<seu-repo>"

Ou em todos os repositórios da máquina (o marcador continua decidindo o que é medido):

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" instalar

Se o repositório já tiver .github/hooks próprios, instale no workspace também: hook de workspace tem precedência sobre o de usuário.

Ligue o OpenTelemetry do Copilot

É daqui que vêm tokens, modelo e custo. Rode uma vez e reabra o VS Code.

setx COPILOT_OTEL_ENABLED true
setx COPILOT_OTEL_FILE_EXPORTER_PATH "C:\Users\i459249\.copilot\harness-metricas\dados\otel\copilot-otel.jsonl"

Alternativa pelo settings.json do usuário: github.copilot.chat.otel.enabled, exporterType: "file" e outfile apontando para o mesmo caminho.

captureContent fica em false

Com true, o OTel grava prompt, resposta e conteúdo de arquivo em disco. Com dado de cliente isso é inaceitável. O padrão já é false — não mude.

Rode o doutor

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" doutor --repo "C:\Users\<voce>\Documents\Projetos\<seu-repo>"

Ele checa Node, pacote, config, pasta de dados, hooks (usuário e repositório), OTel, sessões ativas e erros do coletor — e termina com uma lista do que fazer.

Erro mais comum: pasta errada aberta no VS Code

Para trabalhar e ser medido, abra o seu projeto no VS Code — não a pasta do harness-metricas. A pasta do harness só é aberta se você for editar a configuração dele. Os comandos node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" … rodam de qualquer terminal, inclusive o do seu projeto.

O terminal integrado do VS Code no Windows é PowerShell por padrão. Quase tudo neste manual é node "caminho" …, que é idêntico nos três. O que muda é só isto:

Por que o manual não usa atalho

Um atalho como setx HM … obriga cada pessoa a lembrar o dialeto do terminal em que está, e o erro aparece como ParserError: Token 'ajuda' inesperado — que não parece erro de shell, parece bug do pacote. O caminho completo tem zero ambiguidade. Se ainda assim quiser o atalho, no PowerShell a forma correta é function hm { node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" @args } dentro do seu $PROFILE.

4Conferir se os hooks realmente rodam

Conseguir criar a pasta .github/hooks não prova nada — isso é permissão de disco. Se a política ChatHooks estiver desligada, o VS Code ignora o arquivo em silêncio.

Prova em 1 prompt (canário)

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" verificar-hooks
# feche e reabra o VS Code, mande UM prompt em modo agente que leia um arquivo, e:
node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" verificar-hooks --conferir
node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" verificar-hooks --limpar

Checagens manuais, na ordem

Se estiver bloqueado

O pedido ao admin é específico: liberar a política ChatHooks (setting chat.useHooks) para o seu grupo. Argumento: estes hooks são telemetria read-only, não alteram o comportamento do agente, não injetam contexto e não enviam nada para fora da máquina.

Sem hooks o pacote degrada em vez de morrer: o painel continua com tokens, custo e modelo (via OTel), e perde tempo ativo, guard-rails e o vínculo com atividade.

5Escolher quais sessões são medidas

O modo atual é marcador: nenhuma sessão é gravada até você pedir. Chat exploratório, pergunta rápida, teste de prompt — nada disso entra no painel.

Como ligar a medição de uma sessão

Escreva #medir em qualquer prompt dela — de preferência no primeiro, porque o que vem antes do marcador não é gravado. O prefixo + funciona igual (+medir), útil porque o # abre o seletor de contexto do VS Code.

/sdd-implement REAB-412 primeira fatia de tarefas.md   #medir

analisa o bug do brad-card que some no reload   +medir
O que acontece quando você marca

O coletor grava um SessionStart com o repositório, a branch e o commit do momento, e passa a registrar todos os eventos seguintes daquela sessão até ela acabar. O marcador vale para a sessão inteira — não precisa repetir nos próximos prompts.

Como parar no meio

Escreva #nao-medir no chat. A gravação para na hora; o que já foi coletado continua lá. Para descartar tudo daquela sessão:

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" medir status
# copie o id da sessão e:
node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" ignorar vscode-chat-0f3a…

Ver e administrar

ComandoO que faz
hm medir statusmodo atual, marcador, sessões ativas
hm medir parar <sessao>desliga a medição de uma sessão específica
hm medir limparremove ativações com mais de 7 dias (--tudo limpa todas)
hm ignorar <sessao>exclui a sessão das métricas no build

Outros modos (arquivo config/parametros.json → coleta.modo)

Dá para restringir por repositório em qualquer modo, com coleta.repos_permitidos: ["recr-fed-agc-posvenda"] mede só naquele projeto.

6A rotina de uma tarefa

O que muda no seu dia é uma linha de comando no começo e um marcador no prompt. O resto é o fluxo que você já faz.

Antes de começar: registre a estimativa cega

Quanto essa tarefa levaria sem IA, na sua melhor estimativa, antes de qualquer código. É este número que a gerência vai olhar — e ele só vale como "cego" se for registrado antes da primeira edição de código.

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" estimar REAB-412 32 --nota "planning poker da squad"

Alternativa sem sair do chat: escreva estimativa-sem-ia: 32h no primeiro prompt do /sdd-plan.

No primeiro prompt da tarefa: ligue a medição

Acrescente #medir ao prompt do /sdd-plan (ou do discovery, se o fluxo começar lá).

Trabalhe normalmente

plan → implement → review → archive, cada etapa em sua sessão. Marque cada sessão nova da mesma tarefa — o coletor junta todas pela branch, pelo ticket e pelos artefatos do SDD.

Se a atividade não termina em /sdd-archive

Fluxos de design-to-code, por exemplo, precisam de um sinal explícito de conclusão:

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" concluir REAB-433

No fim do período: gere o painel

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" pendencias
node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" build --de 2026-09-01 --ate 2026-09-30

7Medir uma sessão avulsa (ex.: debug)

Nem todo trabalho passa pelo fluxo SDD. Para uma sessão de depuração entrar no painel como atividade com ganho, ela precisa de três coisas: aparecer como camada própria, ter uma chave de atividade e ter começo e fim.

Uma vez: registre o seu fluxo de depuração

Descubra o nome real do comando ou do agente no repositório:

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" harness listar --repo "C:\Users\<voce>\Documents\Projetos\<seu-repo>"

E registre — troque os nomes pelos que apareceram:

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" toolkit depuracao --comandos depurar --agentes depurador --rotulo "Depuração"

Sem isso a sessão ainda é medida, mas aparece como "sem toolkit" em vez de virar uma camada do painel.

Antes de começar: estimativa e chave da atividade

A chave é o que junta várias sessões numa atividade só. Serve o ticket no prompt, ou uma branch com o ticket no nome. Registre a estimativa cega com a mesma chave:

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" estimar REAB-501 4 --nota "tempo que eu levaria sem IA"

No chat do projeto: marque a sessão

Abra o repositório no VS Code, selecione o agente de depuração e, no primeiro prompt, cite o ticket e o marcador:

/depurar REAB-501 o brad-card some quando recarrego a tela   #medir

Confirme que ligou:

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" medir status

Ao resolver: feche a atividade

Fluxo que não termina em /sdd-archive precisa do sinal explícito de conclusão — sem ele a atividade fica "em andamento" e não entra no cálculo de horas economizadas:

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" concluir REAB-501

Gere o painel

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" build

Se a sessão aparecer solta, em "sessões sem atividade", ligue na mão:

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" medir status
# copie o id e:
node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" vincular <id-da-sessao> REAB-501
Sem ticket, e agora?

Um debug sem ticket ainda rende tempo, tokens, custo e guard-rails na camada de depuração — só não rende "horas economizadas", porque não há estimativa nem atividade concluída para comparar. Se quiser o ganho, invente uma chave estável e use nos dois lugares: node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" estimar debug-brad-card 4 e debug-brad-card escrito no prompt.

8Puxar os harnesses da sua base de código

Seus artefatos vivem dentro de cada repositório de produto. Estes comandos inventariam, copiam entre repos e promovem para o nível de usuário — sem sobrescrever nada por padrão.

1. Ver o que existe hoje

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" harness listar --repo C:\dev\recr-fed-agc-posvenda

Sai o que há em .github/, .agents/ e .claude/ daquele repo, mais o que já está no seu nível de usuário. Rode em cada repo para montar o inventário.

2. Levar de um repo para outro

# sempre simule antes
node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" harness copiar --de C:\dev\repo-origem --para C:\dev\repo-destino --simular

# só os tipos que interessam
node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" harness copiar --de C:\dev\repo-origem --para C:\dev\repo-destino --tipos prompts,skills

# sobrescrever o que já existe no destino
node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" harness copiar --de C:\dev\repo-origem --para C:\dev\repo-destino --forcar

3. Promover para o nível de usuário

O que subir para %USERPROFILE%\.copilot\ passa a valer em todos os repositórios da máquina.

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" harness promover --de C:\dev\recr-fed-agc-posvenda --tipos agents,skills --simular
node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" harness promover --de C:\dev\recr-fed-agc-posvenda --tipos agents,skills

Prompts e instructions de usuário também podem ir para o perfil do VS Code, se é de lá que o seu chat lê:

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" harness promover --de C:\dev\seu-repo --tipos prompts --perfil-vscode "$env:APPDATA\Code\User"

9Gerar o painel e a leitura executiva

O build é determinístico: mesma entrada, mesmo painel. Nenhum número é escrito por LLM.

node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" build
# ou recortando o período
node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" build --de 2026-09-01 --ate 2026-09-30

Saída em C:\Users\i459249\.copilot\harness-metricas\dados\relatorios\<data>\: dashboard.html (é o que você compartilha), dados.json e resumo-narrativa.json.

Leitura executiva (opcional)

Rode o build

Ele grava o resumo-narrativa.json, com cerca de 1 KB.

Chame o agente no Copilot Chat

Selecione o agente metricas-narrador e anexe o resumo:

# readFile resumo-narrativa.json

Ele cria narrativa.md na mesma pasta.

Rode o build de novo

O build confere cada número contra a chave citada no resumo. Número sem chave, chave inexistente ou valor diferente: narrativa recusada, com a lista de problemas no terminal. Só texto conferido entra no painel.

Antes de apresentar para a gerência

Calibre config/calibracao.json com a squad (8 a 10 tarefas já entregues, três devs estimando sem ver o tempo real, mediana por unidade). Enquanto ele estiver com valores de exemplo, o próprio painel exibe um aviso dizendo para não apresentar o ganho como resultado.

10O que é e o que não é gravado

Isto aqui é o que você mostra para o time e para a governança. Há teste automatizado garantindo cada linha desta lista.

Vai para o disco

  • carimbo de tempo de cada evento
  • nome e categoria da ferramenta (readFile, runInTerminal…)
  • caminho relativo do arquivo tocado
  • classe do comando de terminal (teste, lint, validador, git)
  • resultado do comando: sucesso ou falha
  • fato extraído do artefato: ticket, nº de fatias, veredito, contagem de [NÃO RESPONDIDO]
  • tokens, modelo e cache (do OpenTelemetry)

Nunca vai para o disco

  • texto do prompt (só o tamanho em caracteres)
  • conteúdo de arquivo, seu ou gerado
  • texto do comando de terminal (pode conter credencial)
  • resposta da ferramenta
  • caminho absoluto (o nome da sua pasta de usuário é dado pessoal)

Tudo fica em C:\Users\i459249\.copilot\harness-metricas\dados, na sua máquina. Nada é enviado para fora, não há serviço, servidor nem telemetria externa.
