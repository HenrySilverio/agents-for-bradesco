1O que é isso

Duas camadas que convivem: o harness é o que você ensina ao Copilot. O harness-metricas é o que mede se isso deu resultado.

Harness

Seus arquivos de customização do Copilot: instructions, prompts, agents, skills e hooks. É o que faz o agente seguir o padrão do time.

harness-metricas

Um coletor que observa só as sessões que você escolher, e um comando que gera um painel HTML com tempo, guard-rails, tokens, custo e qualidade.

Três regras que evitam quase todo problema

  • Nada é medido sem você pedir. A sessão só é gravada se usar um comando do harness (/sdd-*, /discovery-*) ou se você escrever #medir num prompt.
  • Nenhum conteúdo vai para disco. Nem prompt, nem código, nem texto de comando. Só metadado — veja a seção de privacidade.
  • Zero token. O coletor é Node puro. Nenhum comando aqui chama modelo. A única parte que usa IA é a leitura executiva, e é opcional.

2Instalar (uma vez, ~7 minutos)

Precisa de Node 18+ e nada mais: sem npm install, sem extensão, sem admin.

Coloque a pasta no lugar

O zip traz uma pasta harness-metricas. É ela que vai para C:\Users\i459249\.copilot\harness-metricas. Cuidado com a pasta dentro de pasta que o Windows cria ao extrair.

dir "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs"

Se esse arquivo não aparecer, a pasta está no lugar errado.

Confira o Node

node -v

Precisa ser v18 ou maior.

Crie o atalho hm

Daqui em diante o manual inteiro usa hm. Crie o atalho no terminal que você usa:

Git Bash — acrescente no ~/.bashrc e abra um terminal novo:

alias hm='node "C:/Users/i459249/.copilot/harness-metricas/bin/hm.mjs"'

PowerShell — acrescente no seu $PROFILE (notepad $PROFILE) e abra um terminal novo:

function hm { node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs" @args }

cmd — não tem alias permanente simples; use o caminho completo.

Não quer criar atalho?

Onde o manual escrever hm, digite node "C:\Users\i459249\.copilot\harness-metricas\bin\hm.mjs". Funciona igual nos três terminais, de qualquer pasta. Só é mais longo.

Teste

hm ajuda

Se imprimir a versão e a lista de comandos, está instalado.

Instale os hooks no seu repositório

hm instalar --workspace "C:/Users/<voce>/Documents/Projetos/<seu-repo>"

Isso escreve .github/hooks/harness-metricas.json dentro do repo. Para medir todos os repositórios da máquina de uma vez, rode hm instalar sem --workspace.

Não versione esse arquivo

Rode dentro da pasta do repositório:

# PowerShell
Add-Content .git\info\exclude ".github/hooks/harness-metricas.json"

Ligue a telemetria do Copilot

É de lá que vêm tokens, modelo e custo. No settings.json do usuário:

"github.copilot.chat.otel.enabled": true,
"github.copilot.chat.otel.exporterType": "file",
"github.copilot.chat.otel.outfile": "C:\\Users\\i459249\\.copilot\\harness-metricas\\dados\\otel\\copilot-otel.jsonl",
"github.copilot.chat.otel.captureContent": false

Crie a pasta antes, porque o exportador não cria:

New-Item -ItemType Directory -Force "C:\Users\i459249\.copilot\harness-metricas\dados\otel" | Out-Null

Depois feche o VS Code inteiro — não basta Reload Window — e reabra.

captureContent fica em false

Com true, o OTel grava prompt, resposta e conteúdo de arquivo em disco. Com dado de cliente isso é inaceitável.

Confira tudo de uma vez

hm doutor --repo "C:/Users/<voce>/Documents/Projetos/<seu-repo>"

Ele checa Node, pacote, config, pasta de dados, hooks, precedência de workspace, telemetria e erros do coletor, e termina com a lista do que fazer.

Opcional: o agente da leitura executiva

Só instale agora; só use quando tiver dado de verdade.

O erro mais comum

Para trabalhar e ser medido, abra o seu projeto no VS Code — não a pasta do harness-metricas. Os comandos hm rodam de qualquer terminal, inclusive o do seu projeto.

3Medir uma tarefa do começo ao fim

Este é o uso real. Exemplo com o ticket GPCNLS-9196 e estimativa de 8 horas do planning poker.

Entre na branch da tarefa

git checkout -b feature/GPCNLS-9196

main, master, develop, release/* e hotfix/* são ignoradas pelo coletor: nelas as sessões não se juntam numa atividade.

Registre a estimativa antes de abrir qualquer chat

hm estimar GPCNLS-9196 8 --nota "planning poker da squad"
Antes mesmo. Não depois.

Registrada depois que a primeira linha de código foi editada, ela é marcada como não cega e sai do indicador. É essa trava que faz o número sobreviver a questionamento.

Trabalhe normalmente, em chats separados

Um chat por etapa. Os comandos do harness ligam a medição sozinhos — você não precisa escrever nada a mais:

/sdd-plan GPCNLS-9196 Briefing: docs/briefings/selecao-de-dividas.md

/sdd-implement
/sdd-review
/sdd-archive

O mesmo vale para /discovery-rota, /discovery-triagem, /discovery-grill e /discovery-prototipo, quando o fluxo começa por discovery.

Nunca coloque #medir logo depois do comando

O prompt do SDD lê o primeiro argumento como nome da mudança. /sdd-plan #medir … cria uma pasta chamada medir. Se precisar do marcador, ponha no fim ou numa segunda linha.

Confira que as 4 sessões entraram

hm medir status

Cada sessão aparece com etapa, ticket e número de eventos. Se faltar uma, você descobre agora — não depois do painel pronto.

Veja o que falta antes de gerar o painel

hm pendencias

Lista tudo que impediria o painel de afirmar o que afirma: estimativa faltando, atividade não concluída, modelo sem preço, calibração não feita. Se acusar que a atividade não concluiu (o fluxo não terminou em /sdd-archive), feche na mão:

hm concluir GPCNLS-9196

Se as sessões não se juntarem numa atividade

O vínculo é feito por ticket no prompt, branch e arquivos .sdd/. Quando alguma sessão fica solta, corrija à mão com o id que o hm medir status mostrou:

hm vincular <id-da-sessao> GPCNLS-9196

4Gerar o relatório

Um comando. O painel é um HTML autocontido: abre offline, pode ser anexado no Teams ou impresso.

hm build --saida "C:/Users/<voce>/Documents/Projetos/<seu-repo>/docs/relatorio-metricas" --abrir

Sem --saida, ele escreve em C:\Users\i459249\.copilot\harness-metricas\dados\relatorios\<data>. O --abrir abre no navegador.

ArquivoO que é
dashboard.htmlo painel para apresentar
dados.jsontodos os números crus que o painel usa — é a auditoria
resumo-narrativa.jsoninsumo da leitura executiva (passo opcional abaixo)

Recortar por período

hm build --de 2026-09-01 --ate 2026-09-30

O recorte é por data de conclusão da atividade. Uma tarefa que começou dia 28 e fechou dia 2 cai no mês seguinte — de propósito: ganho só existe depois que a atividade termina.

Não existe filtro por atividade

Escolher quais atividades aparecem depois de ver os números é o viés que destrói a credibilidade do painel. Para tirar uma sessão medida por engano, use hm ignorar — que fica registrado e aparece nas pendências.

Leitura executiva (opcional)

Um parágrafo de contexto escrito por agente, para quem não vai ler gráfico. Só faz sentido com dado real acumulado:

  1. no Copilot Chat, selecione o agente metricas-narrador;
  2. mande #readFile <pasta do relatório>\resumo-narrativa.json;
  3. salve o texto como narrativa.md na mesma pasta;
  4. rode hm build de novo.

O build confere cada número da narrativa contra a chave de origem. Se o agente inventar ou arredondar um valor, o texto é recusado e o painel sai sem ele, com o motivo no terminal. Alucinação não chega à apresentação.

5Fora do fluxo SDD

Debug, chat exploratório, design-to-code: qualquer sessão sem comando do harness precisa do marcador.

Medir um chat qualquer

Escreva #medir em qualquer prompt da sessão — de preferência no primeiro. O prefixo + também funciona (+medir) e evita o menu de variáveis que o VS Code abre ao digitar #.

+medir DEBUG-1 o fluxo de renegociação está estourando no cálculo de parcelas quando…

Sem ticket real, invente uma chave em MAIÚSCULAS com número (DEBUG-1): o vínculo só reconhece esse formato. Use a mesma chave no hm estimar e no hm concluir.

Registrar um toolkit seu

Para que um agente ou comando próprio vire camada no painel, descubra o nome real e registre:

hm harness listar --repo "C:/Users/<voce>/Documents/Projetos/<seu-repo>"

hm toolkit depuracao --agentes depurador --rotulo "Depuração"

O nome tem que bater exatamente com o arquivo .agent.md ou .prompt.md. Confirme depois com hm diagnostico: a linha comandos vistos tem que mostrar o comando.

Duas regras de precedência

Hook de workspace vence o de usuário para o mesmo evento. Agente de usuário com o mesmo nome mascara o do repositório — você edita um arquivo e usa o outro.

Inventariar e mover

# o que existe num repo, mais o que está no seu usuário
hm harness listar --repo C:/dev/seu-repo

# copiar de um repo para outro — simule sempre antes
hm harness copiar --de C:/dev/repo-a --para C:/dev/repo-b --tipos prompts,skills --simular
hm harness copiar --de C:/dev/repo-a --para C:/dev/repo-b --tipos prompts,skills

# promover do repo para o seu usuário (passa a valer em todos os repos)
hm harness promover --de C:/dev/repo-a --tipos agents,skills

Nenhum dos dois sobrescreve arquivo existente sem --forcar.

Política do banco

Não commite nada dentro de .github/ nos repositórios de produto. Deixe local e registre no .git\info\exclude. Se a restrição for só sobre .github/, .agents/skills/ é a alternativa para skills.

7O que é e o que não é gravado

Isto roda em máquina de banco. A regra é: metadado sim, conteúdo nunca.

Gravado
  • carimbo de tempo de cada evento
  • nome da ferramenta e categoria (leitura, edição, terminal)
  • classe do comando de terminal (teste, build, lint) — nunca o texto
  • caminho relativo de arquivo tocado, e quantas linhas mudaram
  • ticket, branch e nome da mudança SDD
  • tokens, modelo e cache, vindos da telemetria do Copilot
  • tamanho do prompt em caracteres
Nunca gravado
  • texto de prompt ou de resposta
  • conteúdo de arquivo
  • texto de comando de terminal (pode ter credencial)
  • qualquer dado de cliente

Tudo fica em C:\Users\i459249\.copilot\harness-metricas\dados, na sua máquina. Nada sai dali: não há servidor, não há envio. Para conferir com os próprios olhos, abra qualquer arquivo em dados\eventos\ — é JSON por linha, legível.

A telemetria do Copilot fica com captureContent: false. Com true ela grava prompt e conteúdo de arquivo — não mude.

Provar que os hooks executam

Conseguir criar a pasta .github/hooks não prova nada — isso é permissão de disco. Se a política ChatHooks estiver desligada, o VS Code ignora o arquivo em silêncio. O canário prova em um prompt:

hm verificar-hooks
# feche e reabra o VS Code, mande UM prompt em modo agente que leia um arquivo, e:
hm verificar-hooks --conferir
hm verificar-hooks --limpar

Para saber se é política corporativa: Ctrl+Shift+P → Developer: Policy Diagnostics. Se ChatHooks aparecer em Non-applied Policy, não está bloqueado — o problema é local.

Quando a telemetria escreve mas o painel não lê

Se o hm diagnostico mostrar muitas linhas e zero spans, o formato do arquivo mudou. Este comando imprime a forma do arquivo — chaves e tipos, sem nenhum valor de texto — para mandar a quem mantém o pacote:

hm diagnostico --otel-cru

10Glossário

TermoO que é
Sessãouma conversa do Copilot Chat, do primeiro prompt até você fechar. É a unidade que o coletor grava.
Atividadea tarefa de negócio (um ticket). Junta várias sessões: discovery, plan, implement, review, archive.
Hookscript que o VS Code executa em momentos do ciclo do agente. Aqui ele só observa.
OpenTelemetry (OTel)padrão de telemetria. O Copilot exporta cada chamada ao modelo para um arquivo — é de lá que saem tokens, modelo e cache.
Guard-railbarreira que impediu uma ação ou exigiu confirmação: hook de guarda, portão do validador SDD, invariante de git.
Estimativa cegaquanto a tarefa levaria sem IA, registrada antes de a execução começar. Registrada depois, não conta.
Tabela de calibraçãohoras por unidade de trabalho (fatia, componente, briefing) acordadas pela squad. Sem calibrar, não vale como referência.
AI Creditsunidade de cobrança do Copilot desde junho de 2026, calculada por token. 1 crédito = US$ 0,01.
